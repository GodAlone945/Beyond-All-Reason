## 3. 开局与游玩

1. 进入本机 **BAR PVE 0.1.0-dev.3** 房间，确认所有参与者使用同一源码/发布包和引擎。启动器“开发”按钮当前只创建普通 BAR PVE 单人 startscript，**不自动开启 Roguelike**；测试 Roguelike 优先通过房间选项。
2. 开启 `_DEV` 中的 `roguelike_mode`。单人保持 `roguelike_coop=0`；双人改为 `1`，两人不同 Team、同一 AllyTeam、每 Team 恰好一名玩家。不要用原版 `coop` 同 Team 共享指挥官功能替代。
3. 基础 Roguelike 不需要再加 Raptors/Scavengers AI；它们的独立刷怪器可能与本模式同时运行。单人和双人先采用纯 Roguelike 配置。
4. 普通游玩 `roguelike_weapon_effect_tests=0`；只有验证地图点选陨石命令和 ARM 测试分裂弹时才设为 `1`。自动商店陨石不依赖此开关。
5. 开始后用 **F1** 开关商店；已有待选卡时可用 **1/2/3** 选择。属性可重复购买到上限；阵营武器购买与装备状态分开。开局准备后持续刷怪，商店无需等待波次结束。
6. 打开设置或回到房间覆盖层时 Roguelike UI 应隐藏并停止处理购买/选卡快捷键；返回对局后恢复。购买后不应跳回列表顶部，已升级列表应独立分行且可拖动。

经济注意：初始金属产出为 0，但当前代码仍有 `每次选卡 +0.1 金属/秒`，跳过卡也有一次性奖励；因此“全程只靠残骸”尚不是当前实际规则。本轮只标出这一口径冲突，没有悄悄改变经济平衡。

## 4. 房间设置与 Boss 权限

三个 Roguelike 选项都在 `modoptions.lua` 的 `section=dev`，默认关闭；`_DEV` 本身标记 hidden，客户端可能隐藏该分组。这与“选项不存在于游戏包”是不同问题。

在停止的对局、玩家身份且具有该房间命令权限时，可先查询再设置：

```text
!list bSettings
!bSet roguelike_mode 1
!bSet roguelike_coop 1
!bSet roguelike_weapon_effect_tests 0
```

单人把第二条设置值改为 `0`。先加载预设再设置模式：本机 `battlePresets.conf` 中多个预设包含 `resetoptions:1`，加载后应重新核对模式值。

| 现象 | 核查路径 |
|---|---|
| `not allowed ... current context` | 实际服务端 Boss/用户权限、是否为玩家而非旁观者、对局是否停止；本机 bSet/bPreset/hPreset/preset 的首条规则均要求 `battle,pv:player:stopped` |
| `not a valid battle setting` | 当前房间游戏包、SPADS 缓存的选项列表；确认 `!list bSettings` 含该 key，更新源码后在空闲窗口重新扫描/托管 |
| Boss 加载配置后退出房间 | 本机 spads.pl 有 Boss 消息洪水豁免补丁；这是服务器侧修改，**不在本游戏仓库内**，更换服务器或更新 SPADS 后需核对是否保留 |
| `Choose in game ... no start box` | StartPosType=2 时设置合法出生框，或选地图支持的其他起点方式；不要靠反复 forceStart 掩盖配置缺失 |
| 模式勾选但 UI/功能缺失 | 同时核对最终 startscript、实际加载游戏名、LuaRules/LuaUI 错误、RML Widget 加载与本地覆盖层；不要只凭房间勾选框判断 |

Boss 不是服务器管理员的同义词。SPADS 帮助明确 `!boss <用户名>` 用来指定 Boss，**无参数 `!boss` 是关闭 Boss 模式**。`!bPreset` 加载战斗预设，`!hPreset` 加载托管预设，`!preset` 切全局预设，不能混用。

## 5. 本地开发与朋友联机

此次只读快照：客户端 `data/games/BAR-PVE.sdd` 和服务器 `pve-data/games/BAR-PVE.sdd` 均链接到本仓库；本地预设游戏名为 dev.3。服务器的发布状态 `server-version.json` 仍指向 **dev.2**，这是开发入口与发行入口的版本分叉；不能据此声称远端朋友已拿到本轮修改。

- 修改源码后，用新对局加载；同名目录链接不是独立构建产物，也不是联机一致性证明。
- 检查工具生成 Roguelike 文件指纹，可辅助比对相关源码；正式发布还需完整游戏包和引擎校验。上次 startscript 是历史开局记录，不代表当前房间实时设置。
- 发布前把应发布的新增文件纳入版本控制，再按现有分发流程生成版本、包校验及服务器状态。当前很多核心文件仍未被 Git 跟踪，仅看 `git diff` 会漏掉它们。
- SPADS 权限、Boss 洪水豁免、本机路径与服务管理位于 `BAR-Server`，要随部署记录维护；游戏 Lua 修改不能替代这些服务器设置。
- 本轮未改外部服务器权限、未重启服务、未提交/发布；`.preview` 为本地验证工具和备份，不作为游戏资源发布。

## 6. 接下来按什么顺序验证

| 顺序 | 验收范围 | 通过标准 |
|---|---|---|
| A | 版本、房间、单人关闭/开启模式 | 最终 startscript 与游戏/引擎一致；普通模式无 Rogue 副作用 |
| B | 单人前三波 + UI | 三阵营普攻、回血、电耗、残骸、F1/ESC/三列/滚动/卡片均正常；无 Lua 错误 |
| C | 六种效果 + 陨石/分裂 | 计数器与实际生成相符、预算满时等待、伤害倍率只算一次、敌我/护盾/D-Gun/精英/Boss 回归 |
| D | 双客户端八波 | 同阵营不同升级不串号、同时购买/选卡只扣一次、断线重连 UI 正确、一人死亡后幸存者继续 |
| E | 扩展人数后才做四人长局 | 先修改并验收当前“恰好两人”门槛；再测第15–20波模拟速度、FPS、Gadget耗时、峰值与回放 |

每条结果记录代码版本/指纹、地图、选项、人数、引擎、日志/回放路径。源码检查、模拟测试、引擎加载、真实游玩分别标记；不相互代替。
